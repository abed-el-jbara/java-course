قاموس المصطلحات المعتمد

فئة (Class) — القالب الذي يحدد الخصائص والعمليات.

كائن (Object) — نسخة محددة من فئة.

خاصية (Property / Attribute / Field) — معلومة محفوظة داخل الكائن.

عملية (Method) — قدرة أو خدمة يوفرها الكائن.

دالة / عملية (Function) — كود ينفذ مهمة ويستطيع استقبال معاملات وإعادة قيمة.

عملية بناء / الباني (Constructor) — عملية خاصة لإنشاء الكائن وتهيئة خصائصه.

عملية بناء ناسخة / باني النسخ (Copy Constructor) — تنشئ كائنًا جديدًا هو نسخة من كائن آخر.

مُعامل / بارامتر (Parameter) — متغير في عنوان العملية يستقبل قيمة عند الاستدعاء.

عملية استرجاع (Getter) — تعيد قيمة خاصية للمستخدم.

عملية تعديل (Setter) — تحدّث قيمة خاصية مع الحفاظ على صلاحية الكائن.

مرجع / عنوان الكائن (Reference) — القيمة التي تشير إلى مكان الكائن في الذاكرة.

الإشارة إلى نفس الكائن (Aliasing) — وجود أكثر من مرجع يشير إلى نفس الكائن.

مؤشر المصفوفة / فهرس (Array Index / Index) — المكان العددي لعنصر داخل مصفوفة.

عداد الحلقة / مؤشر / فهرس (Loop Counter / Index) — متغير مثل i يتحرك أثناء الحلقة.

رمز (char) — قيمة حرفية واحدة.

رموز (Characters) — مجموعة من القيم الحرفية.

واجهة الاستخدام (API) — المعلومات والعمليات العامة التي تتيح استخدام الفئة.

تحميل زائد (Overloading) — وجود عمليات بالاسم نفسه لكن بقوائم معاملات مختلفة.

الكائن الحالي (this) — الكائن الذي نُفّذت عليه العملية الآن.

4.1 - الفئات (Classes) والكائنات (Objects)

الفكرة الأساسية

الفئة (Class) هي وصف عام أو قالب. الكائن (Object) هو حالة محددة أُنشئت من هذا القالب. مثلًا: "سيارة" يمكن أن تكون فئة، أما سيارة محددة برقم تسجيل معيّن فهي كائن.

فكّر هكذا: الفئة تحدد ما الذي نعرفه عن كل كائن وما الذي يستطيع فعله. كل كائن يحتفظ بقيمه الخاصة.

مكونات الفئة

في هذا الفصل نقسم الفئة عادة إلى ثلاثة أجزاء أساسية:

الخصائص (Properties): القيم التي تصف حالة الكائن.
عملية البناء / الباني (Constructor): تنشئ الكائن وتضع القيم الأولية في خصائصه.
العمليات (Methods): الخدمات التي يمكن طلبها من الكائن.
public class Time {
private int _hour;
private int _minute;
public Time(int hour, int minute) {
_hour = hour;
_minute = minute;
}
public String toString() {
return _hour + ":" + _minute;
}
}

إنشاء كائن باستخدام new

Time t1 = new Time(12, 45);
Time t2 = new Time(9, 20);

المتغيران t1 و t2 لا يحتويان "الوقت" نفسه؛ كل واحد منهما يحمل مرجعًا / عنوان الكائن (Reference) إلى كائن مستقل في الذاكرة.

العملية toString()

العملية toString() تُرجع سلسلة نصية تمثل الكائن. عند طباعة كائن باستخدام System.out.println(...)، تستدعي Java العملية toString() تلقائيًا.
public String toString() {
String h = (_hour < 10 ? "0" : "") + _hour;
String m = (_minute < 10 ? "0" : "") + _minute;
return h + ":" + m;
}

المعامل الثلاثي (Ternary Operator) ?:

هو طريقة مختصرة لاختيار قيمة من قيمتين حسب شرط.

condition ? valueIfTrue : valueIfFalse;
String s = (_hour < 10) ? "0" : "";
لا تخلط: المعامل الثلاثي يعيد قيمة. أما if فيُستخدم لتنفيذ أوامر حسب شرط.

تدريب: فئة Movie

1) عرّف فئة Movie بخصائص: اسم الفيلم، اسم المخرج، سنة الإصدار.
2) اكتب عملية بناء تستقبل القيم الثلاث.
3) اكتب toString() مناسبة.
4) في main أنشئ ثلاثة أفلام واطبعها.

4.2 - صلاحية الكائن (Object Validity) والتغليف (Encapsulation)

من المسؤول عن صلاحية الكائن؟

الفئة نفسها مسؤولة عن منع إنشاء كائن غير صالح. المستخدم قد يرسل قيمًا خاطئة، لكن عملية البناء / الباني (Constructor) يجب أن تتعامل معها حسب تعريف الفئة.

مثال Time

الساعة _hour صالحة من 0 حتى 23.
الدقيقة _minute صالحة من 0 حتى 59.
في المادة الأصلية استُخدمت قيم افتراضية عند وصول قيمة غير صالحة: الساعة 8 والدقيقة 30.
public static final int DEF_HOUR = 8;
public static final int DEF_MINUTE = 30;
public Time(int hour, int minute) {
_hour = DEF_HOUR;
_minute = DEF_MINUTE;
if (validHour(hour))
_hour = hour;
if (validMinute(minute))
_minute = minute;
}

لماذا private؟

عندما تكون الخصائص private لا يستطيع المستخدم تغييرها مباشرة. هذا يسمى التغليف (Encapsulation). الوصول والتعديل يتمان عبر عمليات الفئة، ولذلك تستطيع الفئة الحفاظ على صلاحية الكائن.
private int _hour;
private int _minute;

عمليات خاصة لفحص الصلاحية

private boolean validHour(int hour) {
return hour >= 0 && hour <= 23;
}
private boolean validMinute(int minute) {
return minute >= 0 && minute <= 59;
}

العملية private مخصصة لمبرمج الفئة وليست جزءًا من الخدمات التي يحصل عليها المستخدم.

عمليات الاسترجاع والتعديل في فئة بسيطة

public int getHour() {
return _hour;
}
public void setHour(int hour) {
if (validHour(hour))
_hour = hour;
}
قاعدة: في عملية التعديل (Setter)، قيمة غير صالحة لا يجب أن تجعل الكائن غير صالح. اتبع بالضبط ما تحدده متطلبات الفئة: تجاهل القيمة، أو استخدم قيمة افتراضية، حسب السؤال.

كيف نختبر الصلاحية؟

على الحدود00:00 و 23:59الحدود مقبولة
أقل من الحد-1:-1تطبيق القيم الافتراضية

4.3 - مقارنة الكائنات (Object Comparison)

لماذا == لا يكفي للكائنات؟

عند مقارنة متغيرين من نوع كائن باستخدام == نفحص عادة هل المرجعان / عنوانا الكائن (References) يشيران إلى نفس الكائن، وليس هل محتوى كائنين مستقلين متساوٍ.

Time t1 = new Time(12, 45);
Time t2 = new Time(12, 45);
System.out.println(t1 == t2); // false

مع أن المحتوى 12:45 في الكائنين، فهما كائنان مختلفان. لذلك نعرّف في الفئة عملية equals(...) التي تحدد معنى التساوي.

equals في Time

public boolean equals(Time t) {
return _hour == t._hour && _minute == t._minute;
}
قاعدة مهمة جدًا: خصائص من نوع أساسي (Primitive) نقارنها عادة بـ ==. خصائص هي كائنات (Objects) نقارن محتواها باستخدام equals(...) الخاص بفئتها.

Aliasing يظهر أيضًا هنا

إذا كتبنا Time t2 = t1; فإن t1 و t2 يشيران إلى نفس الكائن. هذه هي الإشارة إلى نفس الكائن (Aliasing). تغيير الكائن عبر أحد المرجعين يظهر عبر المرجع الآخر.
Time t1 = new Time(12, 45);
Time t2 = t1;
t2.setHour(18);
System.out.println(t1); // 18:45

تدريب: مقارنة Backpack

1) للفئة Backpack خصائص أساسية. اكتب equals تعيد true فقط إذا كانت جميع الخصائص متساوية.
2) اشرح لماذا لا نستخدم == لمقارنة String.

4.4 - العلاقات بين الكائنات (Relations Between Objects)

يمكن أن نعرّف علاقات مناسبة لطبيعة الفئة: قبل/بعد للوقت، أقرب/أبعد لنقطة، أطول/أقصر لفيلم أو حدث، وهكذا. الفئة هي الخبيرة بمعنى العلاقة.

before في Time

public boolean before(Time t) {
if (_hour < t._hour)
return true;
if (_hour == t._hour && _minute < t._minute)
return true;
return false;
}

يمكن أيضًا الاعتماد على عدد الدقائق من منتصف الليل: الوقت الذي يملك قيمة أصغر هو الأسبق.

العلاقة المعاكسة واستخدام this

إذا كانت before مكتوبة ومختبرة، لا نكرر المنطق عند كتابة after. نستفيد من العملية الموجودة.

public boolean after(Time t) {
return t.before(this);
}

الكلمة this تعني الكائن الحالي (Current Object) الذي نُفّذت عليه العملية.

t1.after(t2)
// current object = t1
// parameter = t2
// equivalent to: t2.before(t1)

كتابة مختصرة للعملية المنطقية

// طويل:
if (condition)
return true;
else
return false;
// مختصر وأفضل:
return condition;

تدريب: علاقات جديدة

1) إذا كانت لدينا فئة Student وبها grade، اقترح عملية higherGradeThan(Student s).
2) إذا كانت لدينا فئة Date، ما معنى before(Date d)؟ من المسؤول عن تعريفها؟

4.5 - عمليات الكائن (Object Methods)

الفئة هي الخبيرة

في OOP نفضل أن يطلب المستخدم الخدمة من الكائن بدل أن يعيد كتابة منطق الفئة في البرنامج الرئيسي.

minFromMid - دقائق من منتصف الليل

public int minFromMid() {
return _hour * 60 + _minute;
}

مثال: 04:25 = 4*60 + 25 = 265 دقيقة من منتصف الليل.

difference - المسافة بين وقتين

public int difference(Time t) {
int d = minFromMid() - t.minFromMid();
if (d < 0)
d = -d;
return d;
}

الفكرة: نحول كل وقت إلى عدد دقائق من نقطة بداية واحدة، ثم نحسب الفرق.

عملية تعيد كائنًا جديدًا

في العملية getNext() لا نغيّر الكائن الحالي، بل ننشئ كائنًا جديدًا من الفئة Time يمثل الدقيقة التالية ونعيده.
public Time getNext() {
int h = _hour;
int m = _minute + 1;
if (m == 60) {
m = 0;
h++;
if (h == 24)
h = 0;
}
return new Time(h, m);
}

نسخ متعددة من العملية نفسها - Overloading

public Time getNext()
public Time getNext(int minutes)
public Time getNext(int hours, int minutes)

هذا يسمى التحميل الزائد (Overloading): الاسم نفسه، لكن قائمة المعاملات / البارامترات (Parameters) مختلفة. المترجم يحدد أي عملية يستدعي حسب عدد المعاملات وأنواعها.

توقيع العملية (Signature)

في المادة، توقيع العملية هو اسم العملية وقائمة المعاملات. نوع القيمة المعادة ليس ما يميز بين عمليتين محملتين بالاسم نفسه.

getNext()
getNext(int minutes)
getNext(int hours, int minutes)
فكرة مهمة: إذا كانت لديك عملية مكتوبة ومختبرة تستطيع استخدامها داخل عملية أخرى بدل تكرار المنطق.

تدريب: getNext

1) إذا كان t=07:00، ما نتيجة t.getNext(30)؟
2) ما نتيجة t.getNext(1,30)؟
3) اشرح لماذا من الأفضل استعمال getNext(int minutes) داخل getNext(int hours, int minutes).

4.6 - واجهة الاستخدام (API) وتوثيق العمليات

ما هو API؟

واجهة الاستخدام (API - Application Programming Interface) هي مجموعة العمليات العامة public التي يستطيع مستخدم الفئة استعمالها، مع تعليمات توضّح كيف يستعملها.

الفكرة تشبه دليل استعمال منتج: المستخدم لا يحتاج معرفة كيف نُفذت كل التفاصيل داخليًا، لكنه يحتاج معرفة ما الذي يستطيع طلبه، ما المعاملات المطلوبة، وما النتيجة.

تعليق JavaDoc

/**
* Returns the number of minutes from midnight.
* @return number of minutes from 00:00
*/
public int minFromMid() { ... }
/**
* Returns a new Time after the given number of minutes.
* @param minutes number of minutes to add
* @return the new Time object
*/
public Time getNext(int minutes) { ... }

ماذا يجب أن يعرف الطالب في سؤال API؟

شرح عام وواضح لما تفعله العملية.
لكل مُعامل / بارامتر (Parameter): الاسم ومعناه باستخدام @param.
معنى القيمة المُعادة (Return Value) باستخدام @return إذا كانت العملية تعيد قيمة.
كتابة عنوان العملية بشكل صحيح: الصلاحية، static إذا لزم، نوع القيمة المعادة، الاسم، والمعاملات.
صياغة الامتحان: عندما نقول "اكتبوا عنوان العملية" فالمطلوب عنوان العملية فقط بلا تنفيذ، إلا إذا طُلب التنفيذ في بند آخر.

ملفات Java وملف التنفيذ

ملف المصدر للفئة يحمل عادة الامتداد .java. بعد الترجمة (Compile) ينتج ملف .class. يمكن استخدام الفئة كمنتج إذا كان ملف التنفيذ متاحًا للمشروع.

Documentation في BlueJ

يمكن توليد صفحة توثيق HTML من تعليقات JavaDoc، وهذا يوضح للمستخدم العمليات العامة وطريقة استعمالها.

4.7 - الفئة المركبة (Composite Class)

التعريف

الفئة المركبة هي فئة تحتوي على خاصية واحدة على الأقل هي كائن (Object) من فئة أخرى.

public class Event {
private String _title;
private Time _startTime;
private int _duration;
}

Event فئة مركبة لأن _startTime كائن من الفئة Time. اختيار Time بدل hour وminute منفصلين يسمح بإعادة استخدام صلاحية Time وعملياتها ويمنع تكرار الكود.

عملية بناء لفئة مركبة

public Event(String title, int hour, int minute, int duration) {
_title = title;
_startTime = new Time(hour, minute);
_duration = DEF_DURATION;
if (duration >= MIN_DURATION)
_duration = duration;
}

عملية بناء تستقبل كائنًا

public Event(String title, Time startTime, int duration) {
_title = title;
_startTime = new Time(startTime); // copy!
_duration = DEF_DURATION;
if (duration >= MIN_DURATION)
_duration = duration;
}
لماذا النسخ؟ إذا خزّنا startTime نفسه مباشرة، يصبح للمستخدم ولـ Event مرجعان إلى نفس كائن Time، وقد تتضرر خصوصية Event بسبب Aliasing.

صلاحية الخصائص

صلاحية الخاصية الأساسية مثل duration تبقى مسؤولية Event.
صلاحية كائن Time نفسه مسؤولية الفئة Time.
لكن Event مسؤول عن حماية خصوصية الخاصية _startTime وعدم كشف مرجعها الداخلي.

toString في فئة مركبة

public String toString() {
return "Event " + _title + " start at " + _startTime +
" for " + _duration + " minutes.";
}
عند دمج _startTime مع String، تستعمل Java العملية toString() الخاصة بالفئة Time تلقائيًا.

1) عرّف فئة Package فيها String _code و Person _receiver و int _weight.
2) حدد أي خاصية تجعلها فئة مركبة.
3) إذا استقبلت عملية البناء Person receiver، كيف تمنع Aliasing؟

4.8 - عمليات الاسترجاع (Getters) في الفئة المركبة

للخصائص الأساسية

public String getTitle() {
return _title;
}
public int getDuration() {
return _duration;
}
ملاحظة: عندما تكون الخاصية قيمة بسيطة، فإن عملية الاسترجاع تعيد قيمة لا تسمح للمستخدم بتغيير الخاصية الأصلية داخل الكائن. أمّا عندما تكون الخاصية كائنًا قابلًا للتغيير، فإن إرجاع الكائن نفسه قد يسمح بتغيير محتواه من خارج الكائن. لذلك نُرجع نسخة جديدة منه لتجنّب الإشارة إلى نفس الكائن (Aliasing).

المشكلة مع خاصية هي كائن

// خطأ من ناحية الخصوصية:
public Time getStartTime() {
return _startTime;
}
بهذا الكود يحصل المستخدم على المرجع / عنوان الكائن (Reference) الداخلي نفسه. إذا عدّله، يتغير الكائن Event دون استدعاء عملية تعديل في Event.
Time t = event.getStartTime();
t.setHour(5); // قد يغير startTime داخل event إذا أعدنا المرجع نفسه

الحل: إعادة نسخة

public Time getStartTime() {
return new Time(_startTime);
}

عملية بناء ناسخة / باني النسخ (Copy Constructor)

public Time(Time t) {
_hour = t._hour;
_minute = t._minute;
}
قاعدة ذهبية: Getter لخاصية هي كائن يجب أن يحافظ على خصوصية الكائن المركب. في المادة نحقق ذلك بإرجاع نسخة من الكائن، لا المرجع الداخلي.

صورة الذاكرة التي يجب فهمها

قبل النسخ: متغير المستخدم والخاصية الداخلية يشيران إلى نفس الكائن. هذه الحالة تسمى الإشارة إلى نفس الكائن (Aliasing).
بعد النسخ: كل مرجع يشير إلى كائن مستقل يحمل القيم نفسها.

تدريب: اختبار Getter

1) أنشئ كائنًا من Event ثم خذ كائن Time باستخدام getStartTime().
2) غيّر الكائن الذي استلمته.
3) ما الذي يجب أن يحدث لـ Event إذا كان Getter صحيحًا؟ اشرح.

4.9 - عمليات التعديل (Setters) في الفئة المركبة

Setter لخاصية بسيطة

public void setTitle(String title) {
_title = title;
}

Setter لخاصية لها شروط صلاحية

private boolean validDuration(int duration) {
return duration >= MIN_DURATION;
}
public void setDuration(int duration) {
if (validDuration(duration))
_duration = duration;
}

نستخدم عملية private واحدة لفحص الصلاحية حتى لا نكرر الشرط في عملية البناء وفي Setter.

Setter لخاصية هي كائن - خطر Aliasing

// غير آمن:
public void setStartTime(Time stTime) {
_startTime = stTime;
}

بعد هذا الإسناد، stTime و _startTime يشيران إلى نفس الكائن. المستخدم يستطيع تعديل Event من الخارج.

الحل

public void setStartTime(Time stTime) {
_startTime = new Time(stTime);
}

اختبار جودة Setter

قيمة صالحة: يجب أن يحدث التحديث.
قيمة غير صالحة: يجب ألا يصبح الكائن غير صالح.
إذا كانت الخاصية كائنًا: يجب فحص منع Aliasing بعد التحديث.

عملية بناء إضافية و this(...)

المادة تعرض أيضًا إمكانية وجود أكثر من عملية بناء. يمكن لعملية بناء أن تستدعي عملية بناء أخرى من الفئة نفسها باستخدام this(...). قائمة المعاملات تحدد أي عملية بناء ستعمل.

public Event(String title, int hour, int minute, int duration) {
this(title, new Time(hour, minute), duration);
}
انتبه: this(...) لاستدعاء عملية بناء أخرى يختلف عن this الذي يشير إلى الكائن الحالي داخل عملية عادية.

تدريب: Setter آمن

1) اكتب setOwner(Person owner) لفئة Pet بحيث تمنع Aliasing.
2) كيف تختبر أن setOwner لا يحتفظ بالمرجع نفسه؟

4.10 - العلاقات بين الكائنات المركبة

equals في فئة مركبة

غالبًا نعتبر كائنين متساويين عندما تكون الخصائص التي تحدد المساواة متساوية. الفئة نفسها هي التي تحدد هذه القاعدة.

public boolean equals(Event e) {
return _title.equals(e._title) &&
_startTime.equals(e._startTime) &&
_duration == e._duration;
}
احفظ الفكرة لا السطر: عند مقارنة محتوى كائنات مثل String و Time نستخدم equals(...). أمّا النوع الأساسي int فنقارنه باستخدام ==.

before و after في Event

يمكن تعريف قبل/بعد للحدث حسب وقت البداية. بدل إعادة كتابة مقارنة الساعات والدقائق، نستعمل خبرة Time.

public boolean before(Event e) {
return _startTime.before(e._startTime);
}
public boolean after(Event e) {
return e.before(this);
}

علاقات أخرى

يمكن تعريف حدث أطول من حدث آخر بمقارنة duration، أو علاقة أخرى حسب متطلبات الفئة. المهم أن معنى العلاقة يحدد في الفئة ويستخدم خصائصها وعمليات الفئات التي تتكون منها.

تدريب: Flight

1) إذا كانت Flight تحتوي الخاصية Time _depTime، اكتب فكرة العملية before(Flight f) باستخدام Time.
2) اكتب after(Flight f) باستخدام before فقط.
3) في equals لخصائص String وTime وint: بأي أداة تقارن كل نوع؟

4.11 - عمليات الكائن المركب

الفكرة

الفئة المركبة تستطيع تنفيذ خدمات جديدة بالاعتماد على عمليات الخاصية التي هي كائن. هذا يحقق مبدأ "كل فئة خبيرة في مجالها" ويمنع تكرار المنطق.

getEndTime - وقت نهاية الحدث

public Time getEndTime() {
return _startTime.getNext(_duration);
}

Event لا يحسب الساعات والدقائق بنفسه؛ يطلب من Time إنشاء الوقت بعد duration دقيقة.

تحديث toString باستخدام عملية موجودة

public String toString() {
return _title + " " + _startTime + " - " + getEndTime();
}

overlap - هل حدثان متداخلان؟

لفهم التداخل، فكّر في وقت بداية ونهاية كل حدث. المادة تستخدم عمليات Time مثل before و after مع وقت النهاية بدل مقارنة الساعات والدقائق يدويًا.

public boolean overlap(Event e) {
return (_startTime.before(e.getEndTime()) &&
_startTime.after(e._startTime)) ||
(e._startTime.before(getEndTime()) &&
e._startTime.after(_startTime));
}
المبدأ أهم من الصيغة: حدد تعريف التداخل الذي أعطاه السؤال بدقة، ثم استخدم before/after/getEndTime بدل إعادة بناء منطق Time.

المسافة / الفراغ بين حدثين

إذا كان الحدثان متداخلين فليس بينهما فراغ. إذا لم يتداخلا، نحسب الفرق بين نهاية الحدث الأول وبداية الآخر. المادة تجمع هنا بين overlap و getEndTime وعمليات Time.

مثال Flight

في تمارين الفصل تُطبق الفكرة نفسها على Flight: حساب وقت الوصول من وقت الإقلاع والمدة، فحص التداخل بين رحلتين، واستخدام عمليات Time بدل تكرار منطق الوقت.

تدريب: عمليات مركبة

1) اكتب getArrivalTime لفئة Flight إذا كانت تحتوي _depTime و _duration.
2) اشرح كيف تفحص overlap بين رحلتين دون مقارنة hour/minute مباشرة.
3) لماذا من الأفضل استعمال عمليات Time الموجودة؟

4.12 - الاختبارات الآلية (Automatic Tests)

لماذا نختبر؟

اختبار البرمجيات يفحص أن البرنامج يطابق المتطلبات. الاختبار الجيد لا يفحص حالة ناجحة واحدة فقط، بل حالات مختلفة تكشف أخطاء الحدود والصلاحية والخصوصية.

اختبار آلي

بدل قراءة كل طباعة يدويًا، برنامج الاختبار يقارن النتيجة الفعلية بالنتيجة المتوقعة ويبلغ Pass/Fail أو يستخدم assertEquals عند توفر بيئة الاختبار.

1. اختبار عملية البناء

بعد إنشاء الكائن، افحص أن الخصائص تحمل القيم المتوقعة. اختبر داخل المجال، الحدود، وخارج المجال من الجهتين، وكذلك خطأ في خاصية واحدة فقط.

2. اختبار Getters و Setters
Getter: هل يعيد القيمة الصحيحة؟
Setter: قيم صالحة على الحدود وداخل المجال يجب أن تُحدّث.
Setter: قيم غير صالحة يجب ألا تفسد صلاحية الكائن.
Getter/Setter لخاصية هي كائن: يجب أيضًا فحص منع Aliasing.
3. اختبار equals / before / after
equals: كائنان متساويان، ثم حالات يختلف فيها كل نوع من الخصائص على حدة.
before: حالة قبل، حالة بعد، وحالة تساوي.
after: حالة بعد، حالة قبل، وحالة تساوي.
4. اختبار عمليات تعيد قيمة أساسية

مثال minFromMid و difference: اختبر حالات سهلة للحساب، حدود اليوم، ترتيبين مختلفين للكائنات إذا كان الفرق يجب أن يكون موجبًا، وحالات تساوي.

5. اختبار عمليات تعيد كائنًا

في getNext(...) لا يكفي التأكد أن عاد كائن. يجب فحص خصائص الكائن الناتج: انتقال دقيقة عادي، انتقال إلى ساعة جديدة, نهاية اليوم من 23:59 إلى 00:00، ومعاملات مختلفة.

6. اختبار Aliasing

هذه من أهم اختبارات الفئة المركبة: احصل على الكائن الداخلي عبر Getter أو مرّر كائنًا عبر Setter/Constructor، غيّر الكائن الخارجي، ثم تأكد أن الخاصية الداخلية لم تتغير.

Time t = event.getStartTime();
t.setHour(3);
if (event.getStartTime().getHour() == 3)
System.out.println("Error - Aliasing");
else
System.out.println("Pass");

تدريب: Tester لفئة جديدة

1) لفئة Person برقم هاتف من 10 رموز: اقترح اختبارات لعملية البناء.
2) لفئة Pet التي تحتوي Person _owner: اقترح اختبار Aliasing لـ getOwner.
3) لفئة Flight: اقترح اختبارات لـ before/after و getArrivalTime.

كيف تحل سؤال فئات جديدًا في الامتحان؟

خطة عمل ثابتة

1. اقرأ تعريف الفئة وحدد كل خاصية ونوعها.
2. حدد أي خصائص لها شروط صلاحية وقيم افتراضية.
3. حدد هل توجد خاصية هي كائن؛ إذا نعم، انتبه مباشرة إلى Aliasing.
4. في عملية البناء: هيّئ كل الخصائص واحفظ الصلاحية والخصوصية.
5. في equals: قارن كل خاصية بالطريقة المناسبة لنوعها.
6. في Getter لخاصية هي كائن: أعد نسخة إذا كان المطلوب حماية الخصوصية.
7. في Setter لخاصية هي كائن: خزّن نسخة، لا المرجع الخارجي.
8. في علاقة before/after: استعمل عملية موجودة إن أمكن ولا تكرر المنطق.
9. في عملية مركبة: استعمل خبرة الفئة التي هي خاصية.
10. في Tester: ابدأ من المتطلبات، واختبر حدودًا، أخطاء، ومشكلة Aliasing.

أخطاء شائعة

استخدام == لمقارنة محتوى String أو كائنين مستقلين.
إرجاع الخاصية الكائنية مباشرة من Getter.
حفظ كائن المعامل مباشرة داخل خاصية كائنية في Constructor/Setter.
نسيان القيم الافتراضية أو حدود الصلاحية.
كتابة منطق مكرر بدل استخدام عملية موجودة.
نسيان أن after يمكن أن تُكتب بواسطة before و this.
كتابة تنفيذ كامل عندما السؤال يطلب عنوان العملية فقط.
API بلا @param أو @return عندما يلزم.
اختبار حالة ناجحة واحدة فقط.

مجموعة تدريب شاملة - ليست من أسئلة الامتحان الأصلي

حل هذه الأسئلة بعد إنهاء الفصل. الهدف التأكد أنك تستطيع نقل الفكرة إلى أسماء وفئات جديدة.

مراجعة الفصل الرابع قبل الامتحان

يجب أن أستطيع شرح

□ الفرق بين فئة (Class) وكائن (Object).
□ ما هي خاصية (Property) وعملية (Method) وعملية بناء / الباني (Constructor).
□ ما معنى صلاحية الكائن والتغليف private/public.
□ الفرق بين == و equals عند الكائنات.
□ ما معنى this والكائن الحالي.
□ ما معنى Aliasing ولماذا هو خطر في فئة مركبة.
□ الفرق بين Getter لخاصية أساسية وGetter لخاصية هي كائن.
إذا كانت الخاصية كائنًا (Object)، فعند كتابتها في عملية البناء / الباني (Constructor) أو في عملية التعديل (Setter)، يجب إنشاء نسخة من الكائن لتجنّب الإشارة إلى نفس الكائن (Aliasing).
□ ما هو Copy Constructor.
□ ما هو API وما يجب أن يحتويه.
□ ما هو Overloading وما هو توقيع العملية.
□ كيف تختبر Constructor/Getters/Setters/Relations/Return Object/Aliasing.

يجب أن أستطيع كتابة

□ فئة بسيطة مع خصائص وConstructor وtoString.
□ فحوص صلاحية وعمليات private.
□ Getters وSetters.
□ equals وbefore وafter.
□ عملية تعيد قيمة أساسية وعملية تعيد كائنًا جديدًا.
□ فئة مركبة مع نسخ آمن للكائن الداخلي.
□ Copy Constructor.
□ API وعنوان عملية بلا تنفيذ عند الطلب.
□ Tester يطبع Pass/Error أو يستخدم assert.

اختبار ذاتي سريع

1. لماذا قد تكون نتيجة المقارنة new Time(12,45) == new Time(12,45) هي false؟
2. ما الفرق بين return _startTime; و return new Time(_startTime);؟
3. لماذا _duration == e._duration لكن _title.equals(e._title)؟
4. ماذا يعني other.before(this) داخل after؟
5. ما الحالات التي يجب اختبارها لخاصية مجالها 0..59؟
6. إذا طلب السؤال "اكتبوا عنوان العملية"، هل تكتب جسم العملية؟
7. كيف تمنع Aliasing في Setter يستقبل Person؟
8. لماذا من الأفضل استعمال getNext داخل getEndTime؟
إذا استطعت الإجابة والكتابة دون حفظ مثال بعينه: أنت جاهز جيدًا لمادة الفصل الرابع حتى لو تغيّرت أسماء الفئات في الامتحان.
